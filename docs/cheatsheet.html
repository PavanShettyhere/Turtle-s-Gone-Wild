01 / Laptop terminal

Connect to your Pi

BASH
ssh turtle_guy@192.168.178.164

Opens a remote shell on the Pi. Use ssh followed by username@address—not ssh@username@address. This is your supplied local IP; update it if the Pi’s address changes.

02 / Pi SSH terminal · ROS installed

Quick start + battery check

BASH
source /opt/ros/jazzy/setup.bash
export ROS_DOMAIN_ID=30
ros2 topic echo /battery_state --once

Run these as three separate lines, without trailing backslashes. Loads Jazzy, selects domain 30, then prints one battery message. Requires the robot’s battery publisher to be running; it can wait if no message arrives. Ctrl+C cancels.

03 / Laptop or Pi · every new ROS terminal

Prepare a new ROS terminal

BASH
source /opt/ros/jazzy/setup.bash
export ROS_DOMAIN_ID=30

Loads ROS commands into this Bash shell and sets the discovery domain. Use the same domain on both machines. These commands do not start the robot.

04 / Laptop or Pi

Check your ROS environment

BASH
printenv ROS_DISTRO
printenv ROS_DOMAIN_ID

Expected for this setup: jazzy and 30. Blank output means the variable is unset in this terminal.

05 / Configured ROS terminal

List available topics

BASH
ros2 topic list

Shows discovered topics. Check that /battery_state exists before trying to read it.

06 / Configured ROS terminal

List running nodes

BASH
ros2 node list

Shows discovered ROS nodes. Missing nodes can mean bringup is not running or network discovery is not working.

07 / Configured ROS terminal

Read one battery message

BASH
ros2 topic echo /battery_state --once

Prints one received message and exits. This is a reading command; it does not start a battery publisher or measure the battery by itself.

08 / Configured ROS terminal

Inspect the battery topic

BASH
ros2 topic info /battery_state

Shows the topic type and publisher/subscriber counts. A missing publisher explains why echo may wait.

09 / Laptop or Pi

Identify the machine and OS

BASH
hostname
cat /etc/os-release
dpkg --print-architecture

Checks which computer this terminal controls, its OS, and architecture. Your supplied Pi output verified Ubuntu 24.04.5 LTS, arm64.

10 / Pi terminal

Find the Pi’s current IP

BASH
hostname -I

Shows local network addresses. If SSH stops connecting, check the current address on the Pi or in your router’s device list.

11 / Pi SSH terminal

Leave the SSH session

BASH
exit

Closes this remote shell and returns you to the laptop terminal. It does not shut down the Pi.

12 / Pi terminal only

Shut down the Pi

BASH
sudo shutdown -h now

Stops the operating system immediately on the machine running this command. Confirm you are on the Pi, stop robot activity, then run it. SSH will disconnect. Allow shutdown to finish before removing power.

Two things to remember.

Ctrl + C stops a running terminal command. A new terminal needs its own ROS environment setup.

Copy buttons only copy text; they never run commands. ROS inspection needs the relevant nodes already running. Exact robot bringup commands will be added once your installation is documented.
